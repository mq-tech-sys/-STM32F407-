# 测试步骤（照着点就行）

> 前提：仓库里的 `sim/` 已经启动（双击 `sim\run.bat`），控制台 <http://127.0.0.1:8848> 开着。
> 没启动就双击 `run.bat`，等它打印出「控制台 : http://127.0.0.1:8848」再往下做。

## 先看这里 · 你账号下现在有两套互不相通的主题

实测结论（同一组 AppID / SecretKey，用同一个客户端去订阅）：

| 服务器 | 主题 | 结果 |
|---|---|---|
| `bemfa.com:9501`（老设备云，固件用的） | `lock000` | ✅ 订阅成功 |
| `bemfa.com:9501` | `lock014` | ❌ SUBACK 0x80 拒绝 |
| `mqttv2.bemfa.com:2023`（内测专业版，你新建的那个） | `lock014` | ✅ 订阅成功 |
| `mqttv2.bemfa.com:2023` | `lock000` | ❌ SUBACK 0x80 拒绝 |

也就是说：**`lock000` 在老服务器上，`lock014` 在新服务器上，两套数据不互通。**

而且新服务器目前**没法给小程序用**：`mqttv2.bemfa.com` 上唯一像 WebSocket 的端口 2024
证书已过期（`certificate has expired`），微信会直接拒绝连接。

**所以测试一律用 `lock000` + `bemfa.com:9504/wss`，那个 `lock014` 门磁卡片先放着不用。**
固件也不用改，它本来就连 `bemfa.com:9501` + `lock000`。

## 第 0 步 · 先证明设备在线（30 秒，不需要任何凭据）

这一步只验证「虚拟门锁有没有挂在巴法云上」，跟小程序无关。

1. 看控制台窗口顶部三行字，应该是：

   ```
   主题       : lock000
   巴法云     : bemfa.com:9501  (ClientID = 设备私钥)
   本地 WS    : ws://127.0.0.1:9001
   ```

2. 打开浏览器进 <http://127.0.0.1:8848>，右上角两个状态灯：
   - **巴法云已连** ← 绿色才算
   - **本地 WS 待连** ← 还没小程序连，正常

3. 打开巴法云控制台，点开 `lock000` 这个主题卡片，看 **「订阅者」是不是「在线」**。
   - 在线 → 设备已就位，继续第 1 步
   - 离线 → 设备没连上，直接跳到文末「排错」

4. 在主题卡片下面那个「请输入消息」输入框里，输入：

   ```
   state
   ```

   点「发送」。

5. **预期**：回到 <http://127.0.0.1:8848> 的控制台，「报文」区会多出两行：

   ```
   ← rx  state
   → tx  state=lock
   ```

   蓝的是收到，绿的是设备回复。看到这两行，**设备这一半就彻底通了**，后面所有问题都只可能在小程序侧。

## 第 1 步 · 让小程序连上巴法云

### 1.1 凭据（已实测可用，直接抄）

小程序不能用设备私钥登录（会把设备顶下线），必须用账号密钥。

本机已用下面这组实测通过（`wss://bemfa.com:9504/wss` + 主题 `lock000`，SUBACK=0，
随后发 `fp_list` / `unlock` 等 5 条命令，设备全部应答，共 12 条回包）：

```
AppID      beid_你的AppID
SecretKey  你的SecretKey
```

> ⚠️ 仓库里**不放真实密钥**。自己的 AppID/SecretKey 从巴法云控制台
> 「内测专业版 → 连接密钥」里取，只填进小程序设置页，或者只写在本机
> `sim\CONFIG-MINE.md`（该文件已在 `.gitignore` 里）——**不要提交、不要截图**。

> ⚠️ 别和控制台首页右上角那个 **「私钥」** 搞混了。私钥（`28eccdb351e4bf84ad1390c143846844`）
> 是给设备端当 ClientID 用的，只能填进固件或模拟器，填进小程序会把设备顶下线。

对照关系：

| 小程序设置页 | 填什么 |
|---|---|
| **用户名** | AppID（`beid_` 开头） |
| **密码** | SecretKey（32 位随机字母数字） |

三个不要：

- ❌ 不要填设备私钥（就是固件里那串 `28eccdb351e4bf84ad1390c143846844`），填了会把设备顶下线
- ❌ 不要填主题名 `lock000`
- ❌ 不要留空，留空一定返回 `rc=4 / rc=5`

### 1.2 打开小程序

1. 微信开发者工具 → 导入项目 → 目录选 `D:\code\smart-lock\mini-program`
2. AppID 选「测试号」即可
3. 点「编译」

> 界面是浅色的、底部三个 tab：控制 / 功能 / 设置。

### 1.3 填设置页

点底部 **「设置」**，按下表填（**逐字对照，尤其主题名**）：

| 界面上的字段 | 填什么 |
|---|---|
| 服务器 | `wss://bemfa.com:9504/wss` |
| 主题名 | `lock000` |
| ClientID | `wxmp_lock01` |
| 用户名 | AppID（`beid_` 开头，从巴法云控制台取） |
| 密码 | SecretKey（32 位随机字母数字） |
| KeepAlive | `60` 不用改 |

> ⚠️ 如果这几个框里已经有旧值（比如主题名是 `lock001`），**先点最底下「恢复默认」**，再按上表重填。
> 小程序把配置存在本机，改默认值不会覆盖你已经保存过的旧配置。

填完点 **「保存并立即试连」**。

### 1.4 看控制页

1. 底部切到 **「控制」**
2. 顶部选 **「云端 MQTT」**
3. 点 **「重连」**

**预期**：下方「收发日志」出现设备上线时主动上报的四条：

```
ack=online
num=card,2
num=fp,3
state=lock
```

同时 <http://127.0.0.1:8848> 控制台能看到 `tx state=lock` 等绿色行。

看到这四条 = 小程序 ↔ 巴法云 ↔ 设备 全链路通了。

## 第 2 步 · 验证功能（每点一下都能在控制台看到报文）

| 操作 | 小程序里点 | 预期（收发日志 / 控制台） |
|---|---|---|
| 开锁 | 控制页「开 锁」 | `ack=unlock` → `state=unlock`，**2 秒后自动再收到 `state=lock`**（固件里舵机 2 秒回位），界面自己变回「已上锁」 |
| 上锁 | 控制页「上锁」 | `ack=close` → `state=lock` |
| 查状态 | 控制页「查询」 | `state=lock` |
| 看指纹 | 底部「功能」页 | 列出 `#1 #2 #5` 三条 |
| 删指纹 | 功能页某条右边「删除」→ 弹窗点「删除」 | `ack=fp_del_ok`，列表变两条 |
| 看卡 | 功能页往下滑到「RFID 卡片」 | 列出 2 张，UID 为 `A1B2C3D4`、`1A2B3C4D` |
| 删卡 | 某张卡右边「删除」→ 弹窗点「删除」 | `ack=card_del_ok`，剩一张 |
| 密码开锁 | 功能页最下面「密码」区，输 `123456` | `ack=pwd_ok` → `state=unlock` |

> 功能页的列表是「连上后第一次进入」自动拉的。如果进去看到「正在读取指纹列表…」一直不结束，
> 或者列表是空的，点一下这一区的 **「刷新数量」**。
>
> 删坏了不要紧，控制台页面底部有「**恢复演示数据**」按钮，点一下回到初始状态
> （指纹 #1 #2 #5、2 张卡、密码 123456）。

## 第 3 步 · 不通时怎么定位（别瞎猜，跑它）

```bat
cd /d <仓库路径>\sim
probe.bat --appid 你的appID --secret 你的secretKey
```

它分三段报：

| 输出 | 含义 | 怎么办 |
|---|---|---|
| `[1/3] OK CONNACK rc=0 + SUBACK rc=0` | 设备侧链路正常 | 问题在小程序侧 |
| `[1/3] 失败 订阅 xxx 被拒绝（SUBACK 0x80）` | **主题名和私钥不是一对** | 主题名填错了，改主题不是改密码 |
| `[2/3] 失败 rc=4 / rc=5` | appID 或 secretKey 错 | 重新复制一次，注意别带空格 |
| `[2/3] 超时` | WSS 出不去或域名没放行 | 见下方「关于域名校验」 |
| `CONNACK 已收到、SUBACK 没等到` | 同一个私钥重复登录被顶号 | 关掉模拟器再诊断 |

### 关于域名校验

`wss://bemfa.com:9504/wss` 不是 443 端口，微信默认会拦。本项目 `project.config.json` 里
`urlCheck` 已经是 `false`，等于「不校验合法域名」一直开着，正常不会被拦。

这个开关只对 **开发者工具 / 扫码预览 / 真机调试** 生效，线上正式版一律校验。
个人测试一直用「预览」就行，不要上传体验版。

## 排错：设备连不上巴法云

1. 看控制台顶部状态灯是不是「巴法云已连」
2. 看日志里有没有 `已订阅主题 lock000（rc=0），远程控制就绪`
   - 出现 `SUBACK 被拒绝` 或 `订阅 ... 被拒绝（SUBACK 0x80）` → 主题名和私钥不配对
3. 确认没有第二份程序同时在线（真机和模拟器共用同一个私钥，后连的会顶掉先连的）
4. 确认桌面只有一个模拟器进程：
   ```powershell
   Get-NetTCPConnection -LocalPort 8848 -State Listen
   ```
   正常只有一个 PID。有两个就都 kill 掉，重新双击 `run.bat`。

### 现象：满屏 `err=unknown`，一直刷不停

**原因是开了两个模拟器。** 两个进程都用同一个设备私钥、都订阅 `lock000`，
A 回复的 `help=...` 会送到 B，B 把它当成未知命令再回 `err=unknown` + `help=`，
又回到 A，瞬间变成指数级互刷。

现在已经从两头堵住了：

- 启动时会探测 8848 端口，发现已有实例就直接退出并提示，不会再悄悄开第二份
- 设备收到「像应答」的内容（`ack=…` / `state=…` / `help=…` / `err=…` / `fp=…` / `card=…` / `pong` 等）
  一律丢弃，不再回复 —— 固件里也加了同样的拦截（`remote_cmd.c`）

如果还看到刷屏，按第 4 条查进程，杀干净后重新启动。

### 现象：日志里只有 `→`，一条 `←` 都没有，界面一直「状态未知」

这是**连接假活**：socket 已经废了，但程序还记着「上回连上过」，于是命令照发（`→`），
应答永远收不到（没有 `←`，也没有 `MQTT CONNACK 成功` / `订阅成功` 这两行）。

之前的小程序客户端有两个隐患，已修复（`mini-program/utils/mqtt.js`）：

1. `connect()` 没有复位 `connected` / `online`，旧连接状态会一直留着；
2. 用的是全局 `wx.onSocketXxx`，反复重连会叠加多份回调，旧 socket 的事件可能串到新连接上。

现在改成：

- 每次建链先清状态、关掉上一根 socket；
- 优先用 `SocketTask` 自己的 `onOpen / onMessage`（事件和 socket 一一对应）；
- **8 秒看门狗**：没连上会写「8 秒没能建立 WebSocket…」，连上但没收到 `CONNACK`/订阅应答会写
  「WebSocket 已连上，但 8 秒内没收到 CONNACK 或订阅应答」；
- **假在线检测**：已上线后超过 2×KeepAlive（默认 120 秒）一条报文都没收到，直接判定失效并自动重连。

正常连上时，日志从上到下应出现这五行：

```
← 门锁状态：已上锁          ← 设备应答
订阅成功: lock000           ← 订阅确认
MQTT CONNACK 成功           ← 握手确认
WebSocket 已打开，发送 MQTT CONNECT
正在连接 wss://bemfa.com:9504/wss
```

**注意**：改完要重新点一次「编译」，旧代码还在内存里跑着的话看到的还是老行为。
